# P4.4 — Data Operator screens (ops-web)

Approved by the project owner on 2026-11-15, with the answers to the open questions recorded below.
Each part is done in its own Claude Code session, which starts from this file. Backend changes go in
their own commit before the screens that use them. Nothing is ticked in docs/progress.md; each part
ends with a verdict per ID.

Sources read: CLAUDE.md; docs/decisions.md (P3.3 UI patterns, P4.1 to P4.3 and the open items);
SRS 3.1 ("Content lists and forms", "Needs verification"), FR-DAT-01 to FR-DAT-08, FR-DAT-10,
FR-ADM-04, FR-LOC-03, FR-LOC-04, NFR-06, NFR-14, NFR-15; ops-web; packages/ui; the content module;
the P0.4 spikes.

## Findings that shape the plan

- There is no `RoleGate` component. The gate is `AuthGate roles={[...]}` (FORBIDDEN for any other
  role) with `navItemsFor` for the header links; no second gate is added.
- Every screen lives in `packages/ui/src/screens`; ops-web pages are thin wrappers.
- "Bilingual screen tests" are the Playwright tests that open each screen in English and Arabic and
  fail on any next-intl `MISSING_MESSAGE` in the console, plus the ar/en key-parity unit test.
  packages/ui has no component-test library, and none is added.
- `ApiClient` uses `fetch`, which cannot report upload progress.
- `applyServerFieldErrors` shows every server issue code but `too_small` as "invalid format".
- No CSP is configured (Caddyfile, next.config), so nothing blocks the tiles today.
- Developers and communities already have Data Operator endpoints (`/content/developers`,
  `/content/areas`); a project already returns its developer's and community's names and status.

## Part a — navigation, developers, sales contacts, areas

Navigation: `navItemsFor('ops', 'data_operator')` gains Developers, Sales contacts and Areas
(Projects in b, Needs verification in d, so no link points at a missing page). Every page uses
`AuthGate roles={['data_operator']}`.

Routes (`apps/ops-web/src/app/[locale]/`):
- `/developers`: list with search (q) and a status filter; "New" opens a dialog, then the developer's
  page.
- `/developers/[id]`: edit form (names side by side, descriptions side by side, website), logo upload,
  replace and remove with a preview behind the session, archive or restore (ConfirmDialog;
  DEVELOPER_HAS_PUBLISHED_PROJECTS shown as its message), delete (ConfirmDialog; DEVELOPER_IN_USE
  points to archiving).
- `/sales-contacts`: list with search on name and title only, developer and active filters; a
  create/edit dialog with developer, name, title, phone, WhatsApp, email, languages (typed as a
  comma-separated list, sent as an array), verification date (max = today in the UAE) and source,
  active, and assigned projects as checkboxes of the chosen developer's projects.
- `/areas`: tabs Emirates and Communities and a fixed "Country: United Arab Emirates" line
  (FR-LOC-04); a create/edit dialog with names and descriptions side by side, the emirate of a
  community (active emirates plus the current one), center longitude and latitude as number fields
  with the UAE box as a hint, and active; delete, where AREA_IN_USE suggests deactivating. The map
  picker joins this form in part b.

Shared additions (the one form pattern, extended): `TextAreaField`, `FieldPair` (Arabic and English
side by side, stacked below 768 px, following RTL), a wide `Dialog` option, server issue codes shown
as `validation.server.<code>` when the key exists, `localName()` (FR-LOC-03 fallback), and the
messages in ar and en.

Tests: unit tests for the navigation by role, `localName`, the server issue keys and the languages
parser; the ar/en key-parity test; Playwright `apps/e2e/tests/data-operator.spec.ts` (create a
developer, a contact, an emirate and a community; a center outside the UAE shows its message; role
separation of the links and pages; every Data Operator screen in English and Arabic with no missing
message). No API change.

## Part b — projects, Details, Amenities, map

b1 backend:
- `GET /api/v1/content/reference/:kind?include=<uuid,…>` (`@Roles('data_operator')` on the
  controller class): the ACTIVE items through `ReferenceDataReader.listActive`, plus any ids named in
  `include` (at most 100), marked `isActive: false` when inactive, so a deactivated item already on a
  record still shows its name. Admin gains `ReferenceDataReader.findByIds(kind, ids)`. Kinds: property
  types, layouts, furnishing, unit levels, unit tags, amenity categories, amenities (grouped by
  categoryId in the browser).
- `POST /content/projects/:id/restore`: archived → draft (rule 6 below).
- Tests: allowed role, 403 for the three other roles, 401 without a session; an inactive item absent
  unless included; an amenity of an inactive category absent; a malformed or too long `include` is
  400; restore 409 on draft and published, 404 for an unknown id, editable after restore, absent
  from ProjectReadModel, back in needs-verification.

b2 screens:
- `/projects`: list with status, stage, developer and community filters and q, through a new
  server-paging option of the same DataTable (5,000 projects in the load data). Tests for both modes.
- `/projects/new` (Details only), `/projects/[id]?tab=details|amenities|media|plans|units`. The tab is
  in the URL, so switching language keeps it and blocker links can point to it. Header: status, last
  verified, Restore when archived; an archived project is read-only (disabled fieldset).
- Details: names and descriptions side by side, developer, community, stage, launch date, expected
  handover (quarter, year), actual handover date, ownership and lease term, service charge (decimal
  string), location with the MapPicker and longitude/latitude fields kept in sync.
- Amenities: checkboxes grouped by category; a deactivated amenity on the project shows checked and
  marked "deactivated", and can be unchecked but not checked again.
- MapPicker (`packages/ui/src/map/`): maplibre-gl through a dynamic `import()` only when a map is
  shown (a test checks that a page without a map does not load it); a UAE view; a click sets the
  marker; navigation control; attribution not collapsed; an error state with retry when the style
  fails, while the fields keep working.

## Part c — media, payment plans, units

c1 backend (rule 5 below): `OperatorNamesPort`, `UserDirectory.displayNames(ids)`,
`changedByName` on history entries, tests (including the response shape).

c2 screens:
- Media: type, title, display order, source note and license note (required), then the file through
  a drop zone or a file button; `FormData` appends the text fields first and the file last.
  Type and size checked in the browser against `MEDIA_MAX_BYTES` for a quick message only. A new
  `ApiClient.upload()` on XMLHttpRequest (same CSRF retry and error mapping) with a `<progress>` and
  Cancel (abort). Move up / Move down buttons rewrite displayOrder; edit in a dialog; delete with
  ConfirmDialog (422 licensed_image_missing shown as its message). Drag-and-drop is for upload only.
- Payment plans: plans with a default badge; an editor with name and milestone rows (labels en/ar,
  percentage, timing and its field; add, remove, move); a live total in integer hundredths
  (`packages/ui/src/decimal.ts`, never floats) announced with aria-live; set default; delete
  (DEFAULT_PLAN_REQUIRED).
- Units: DataTable (full list per project, at most 500); inline price (Edit → input, Enter saves,
  Esc cancels) and status (select); a History dialog (UAE time, field, old → new, who: "you", the name,
  or "an operator"); create and edit dialogs with reference selects using `include`; delete
  (UNIT_IN_USE). AED formatted from the decimal string without floats.
- Unit tests: 33.33 + 33.33 + 33.34 = 100.00; 0.1 + 0.2 = 0.30; three decimals refused; AED grouping;
  history name labels.

## Part d — publish, verify, needs verification, e2e

d1: `pnpm --filter @reih/api e2e:read-project --id <uuid>` (rule 11 below), with tests that it refuses
production and non-local targets before connecting.

d2 screens:
- Publish: on 422 PUBLISH_BLOCKED a checklist dialog lists each code with its translated label and a
  link to the tab that fixes it (developer, community, location, stage and handover → Details;
  licensed_image_missing → Media; verification_missing → the Verify dialog). The mapping is a
  `Record<PublishBlocker, …>`, so a new code without a label or tab fails typecheck. Unpublish,
  Archive and Restore through ConfirmDialog.
- Verify dialog: date (UAE today by default, max today), source, notes.
- `/needs-verification`: server-paged in the API's order (never verified first, then oldest), status
  filter, Verify on each row, last verified as the UAE day `YYYY-MM-DD` in `<bdi dir="ltr">`.
- Playwright `content-publish.spec.ts`: developer → community → project → Publish refused with the
  checklist → upload a licensed PNG (progress shown) → a plan 33.33/33.33/33.34 showing 100.00 →
  3 units, an inline price edit adds a history row "by you" → verify → publish →
  `e2e:read-project` returns the project with its licensed image. Plus every project tab and Needs
  verification in English and Arabic with no missing message.

## Decisions on rules 3–6 and 11

Rule 3, map:
- Tiles: OpenFreeMap, Liberty style (`https://tiles.openfreemap.org/styles/liberty`), named in SRS
  3.2 and used by the P0.4 spikes. No API key and no account, so no secret and no env variable; the
  URL is one constant in `packages/ui/src/map/tiles.ts`. Map data © OpenStreetMap contributors
  (ODbL), with © OpenMapTiles and OpenFreeMap credited; MapLibre's AttributionControl shows the
  style's attribution, not collapsed. The exact text is confirmed in part b and recorded here and in
  docs/decisions.md, and the screen test checks that "OpenStreetMap" is visible.
- Open item for deploy (P0.3): the public OpenFreeMap instance is fine for development and the demo
  but has no service guarantee. Keep the one constant, so a guaranteed provider or self-hosted tiles
  can replace it.
- maplibre-gl is not yet a dependency of any workspace package (only spikes/, 6.16.0). Part b adds
  the newest version that passes the one-day release age to packages/ui (where every screen lives),
  loaded with a dynamic import. No other map package. The part b summary states its exact version,
  publish date and license.
- When a CSP is added, it must allow tiles.openfreemap.org (connect, img) and `worker-src blob:`.

Rule 4, reference data: `GET /content/reference/:kind?include=…` as above (active items by default),
inside content, through admin's ReferenceDataReader plus `findByIds`. Content already imports admin.
Communities and developers use the existing content endpoints.

Rule 5, history names: content declares `OperatorNamesPort` (`displayNames(ids) → Map<id, name |
null>`) in `application/ports.ts`; an app-level `@Global()` `content-ports.module.ts` binds it with
`useExisting` to identity's `UserDirectory`, which gains `displayNames`. displayNames returns the
display name only, never an email, phone or anything else, and a test checks the response shape.
Content still imports only admin; identity imports nothing. The history response gains
`changedByName`; the screen shows "you", the name, or "an operator" when no name is set.

Rule 6, restore: `POST …/restore`, archived → draft, the project row locked FOR UPDATE (first in the
lock order), `published_at` kept (so the unit delete rule still treats it as once published), new
error code PROJECT_NOT_ARCHIVED (409), tests. No event: a draft is never visible to brokers or
catalogs, and CLAUDE.md rule 4 lists exactly four events.

Rule 11, e2e: the Data Operator comes from the existing invitation flow: `createPlatformAdmin()`
(the existing command), the Platform Admin invites a data_operator on the Staff screen, the Data
Operator activates from the Mailpit email and logs in. No new account CLI. "Returned by
ProjectReadModel" is checked by `e2e:read-project` (assertE2eAllowed before connecting, a Nest
application context, ProjectReadModel.findPublished and listPublishedMedia, prints
`E2E_READ_PROJECT {json}`); a direct DB read from apps/e2e would copy the read model's filters and
add pg to apps/e2e.

Rules 7–10, 12, 13 are covered in parts c and d. No migration in any part.
