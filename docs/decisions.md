- 2026-11-08 — Session cookie reih_session is a browser-session cookie (no Max-Age or Expires) with HttpOnly, Secure, SameSite=Lax, Path=/. The 8-hour idle timeout is enforced on the server. Secure is always set, because browsers accept Secure cookies on http://localhost too; decided by the project owner — FR-ACC-02, SRS 3.3.
- 2026-11-08 — Sliding expiry is written at most once every 60 seconds (SESSION_TOUCH_INTERVAL_MS), not on every request, to save one database write per request. A session can therefore end up to one minute before 8 hours after the very last request — FR-ACC-02.
- 2026-11-08 — Session tokens are 32 random bytes in base64url; sessions.token_hash stores only their SHA-256 in hex. Each login creates a new session, and a session cookie the browser still sends at login is ended (against session fixation). Sessions on other devices stay open. A session whose user is no longer active is ended on its next request, so access does not depend on the event listener having run — FR-ACC-02, FR-AGY-04.
- 2026-11-08 — CSRF is a double-submit token: GET /api/v1/auth/csrf sets __Host-reih_csrf (HttpOnly, Secure, SameSite=Lax, Path=/, no Domain) and returns the same token, which POST, PUT, PATCH and DELETE send back in X-CSRF-Token, compared in constant time. The __Host- prefix makes browsers refuse the cookie from a sibling subdomain, so the token needs no signing secret and no new environment variable. Login and logout are checked too. An existing well-formed token is reused, so other open tabs keep working — SRS 3.3, NFR-08.
- 2026-11-08 — Global guards run in this order: AuthGuard (session, skipped on @Public()), CsrfGuard, RolesGuard. An endpoint that is neither @Public() nor @Roles() is refused with 403, so a forgotten declaration fails closed. Roles and CurrentUser are exported from identity/index.ts — FR-ACC-04, NFR-09.
